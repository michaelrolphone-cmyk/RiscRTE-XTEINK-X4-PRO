# X4 0.1.100 shared keyboard integration

The .100 recipe consumes the frozen published .99 image (product 199e231d),
retaining its Runtime 0.2.28 HTTPS memory fixes, Hollow 1.2.2, OBD 0.2.1,
Files 1.5.31, Home 0.4.13, boot-order packing and capability authority.

Published System c2889adff2a06bcd6c6207f11fbd0795fbbd99fa supplies the matched
scene-host 0.4.2 and text-input-host 0.1.4 pair. It fixes short physical-release
capture under raster load, ordered reused contact IDs and repeated letters,
and adds masked-by-default password Show/Hide with remasking and secret cleanup.
The source-bound tests include real Runtime/Graph execution, synthetic GT911
capture stress, Watch/X4/gray scene profiles, native-retention privacy fences,
raster equality and complete target relocation checks. Simulated timing is not
physical latency measurement.

Only six internal files change: cohort metadata, the two provider binaries and
manifests, and their immutable SD image paths in boot.json. Existing SD contents
are retained; the new cumulative overlay adds only the selected provider pair
alongside required .98/.99 OBD/Hollow updates. Apply it over the already required
.96 SD baseline without deleting existing files. Full initial flashing erases
internal saved data; unfinished SD-first settings persistence is not enabled.

The recipe checks the exact .99 image/receipt/inventories, all compiled provider
sources and SDK headers, matching shared keyboard ABI, deterministic boot-order
packing, immutable SD selection/fallback parity, independent final-image decode,
bank authentication and byte equality outside bootfs/bank-state ranges.
qualify_keyboard_100.py admits all 43 internal and 48 selected SD ELFs with the
exact native resolver in normal and ASan/UBSan modes, including OBD/Hollow catalog
contracts. Hardware behavior and live heap headroom remain untested.

## Remaining universal-keyboard work

The frozen X4 Wi-Fi 1.1.27, Points 0.6.17 and BLE Scanner 0.2.24 already request
ui.text-input and receive this correction. Files 1.5.31 still uses its legacy
editor. This product retains the existing touch-only text-host dependency
selection. The shared provider's hardware-keyboard paths are covered by tests,
but the USB keyboard dependency is not bound into this frozen product graph.
This corrective build is not a claim that every editor or hardware-keyboard
consumer has completed the broader migration.
