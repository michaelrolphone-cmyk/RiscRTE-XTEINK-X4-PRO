# .87 manual lock entry regression

Exact delivered X4 `24fc5b7e8e7cee9d0150dbca2a4036fc21e2cbc4` / Runtime `c3d750d113dbc79af87daaad316ab1d63d57dd60` has no retained_wake_bytes opt-in. Native capacity is 128. The retained Home 0.4.10 binary was built with PORTABLE_DESK_POINTS_SNAPSHOT: schema 3 needs 408 bytes. Working .81/.83 receipts selected 512; .84-.87 omitted that independent build option.

Production Home, shared adapter/renderer and exact .87 local sleep hook reproduce an apparent unlock: native capacity 128 makes desk_stage refuse the record, restores resources and returns to unlocked Home without calling native deep entry at all. Thus this reproduced failure is NOT proof of an RTC/button spurious wake. No hardware has been read or flashed, so a distinct observed physical deep-wake failure remains possible.

Focused correction: preserve .87 Runtime and USB/native retention fixes, explicitly add `--retained-wake-bytes 512`. The full-image assembler now rejects this selected Home composition unless the option is present; existing native proof verifies its linked marker and payload size. No app/provider byte changes are needed for this capacity correction. The product release integrator owns the next version/tag; do not overwrite delivered .87 identity.

Regression source is System Apps scripts/test_shared_quick_home.py --lock-regression-only. Tests run actual Home/sleep code with strict native boundary models at 128 and 512 bytes; unrelated Contexts/catalog/crash/idle profiles are explicitly excluded from that focused host fixture, never from the product. Normal and UBSan runs reproduce 128 refusal; 512 enters deep, preserves both landscape directions, and survives 32 successive retained timer boots with no foreground promotion or unlock. GPIO wake only advances after the held-key neutral gate. Existing RTC native classification maps timer to DEEP_TIMER and GPIO/EXT0/EXT1 to DEEP_GPIO; X4 deep entry arms its owned GPIO3 and a timer. Provider release/entry neutrality still rejects a held power key.

Limits: software boundary qualification, not hardware wake-source measurement. Clean timer-cycle failure/foreground-promotion policy and corrupt/missing retained records need separate review; this focused correction does not claim those paths have become a secure lock. The reported user persistence issue is a separate shared-settings change and must not delay this checkpoint.
