# X4 0.1.98: OBD on the qualified Files .97 baseline

This source adds OBD Dashboard 0.2.1, scene 0.4.1 and BLE serial 0.1.0 to the exact
published .97 source e9332c3fe731ed63508e223bcd67cedf481462e4. It does not use the
historical .88 firmware recipe as its product baseline.

The .97 native firmware, Home 0.4.13, Files 1.5.31 and all 81 existing SD files
remain byte-identical. The thirteen .96 foreground lifecycle manifests remain.
Startup filesystem placement uses the unchanged .95 boot-order algorithm.
No general installation grants, namespace ownership or shared-settings policy
are broadened. The OBD application has one explicit catalog reservation granting
only scene, BLE serial and SD volume 9, with an explicit foreground descriptor.

## Published components

`../obd-098-components.json` binds the exact repository commits, trees and target
ELF hashes. The shared System source is a union of published Files 0accd890 and
OBD scene b5cc754, at 49752a02746b38afbcc403bb92189be5a8356c9d. This preserves the
newer native exit handling and clipped/color painting missing from historical
scene 0.4.0. Scene 0.4.1 and app 0.2.1 reproduce their qualified target bytes from
this union. Their exact-head CI is successful.

Application 0.2.1 fixes a late reconnect edge: a peer found in the final scan
poll must not be immediately closed by the preceding SCAN_DONE snapshot. It
also handles BLE reload-required state without endless retries. The recovery
screen requires closing OBD and restarting the device, because demand-retained
provider pins mean simply reopening the app does not guarantee fresh globals.
A failed close still retains the invocation and its BLE custody.

LIVE, GRAPH, FAULTS and INFO, diagnostic reads, VIN, readiness, freeze frames,
sensor configuration, saved preferences, recording and confirmed code clearing
remain. Development performs no vehicle or adapter operation.

## Qualification and limits

Normal and ASan/UBSan app tests cover 16 actual app/scene scenarios, including
four new reconnect/recovery cases; protocol/model/math tests also pass. Shared
scene coverage includes 179 presenter/profile executions and existing Reader,
component and checkpoint checks. The BLE serial driver passes 10 real-NimBLE
protocol cases per normal/sanitizer mode. The late reconnect regression fails
before the fix. Target ELFs are reproduced by CI.

Final product qualification must retain its separate complete-image admission,
selected-SD admission, native installed-catalog checks, negative/preservation
probes and filesystem readback receipts. Host fixtures do not execute Xtensa
instructions or establish physical adapter compatibility, radio reliability,
vehicle correctness, or real wake latency.

The transport is BLE GATT serial. Classic Bluetooth SPP, Wi-Fi ELM adapters,
pairing-required endpoints and unrecognized vendor protocols remain unverified.
The owner must test the actual adapter while safely parked. No code-clearing
action was performed during development; existing fresh stopped-engine and
stopped-vehicle checks, explicit confirmation and ECU acknowledgment remain.

## Reproduction

Use the exact public .97 delivery folder and source-pinned component outputs.
Run `minimal/test/obd_098_composition_test.py` with --baseline, --app, --scene,
--driver, --tools and --runtime. Run `compose_obd_098.py` with those component
paths, --runtime-source, --product-revision (clean published .98 source), and a
new --output folder. The recipe verifies baseline receipt, full image, every
store/SD file and native component, component source/build identities, resident
descriptor, deterministic packing, unchanged flash ranges and paired hashes.

Use the strict installed-catalog qualifier with provider capacity 40 and shared
Files enabled, the exact unchanged .97 native BIN and ELF, and the generated
store. Admit all 48 selected SD images separately and run
`test_obd_native_catalog.py` against the exact store in normal and sanitizer
modes. Keep hardware testing distinct from these source and host checks.

## Install warning

The 16 MiB full-initial image is flashed at offset 0x0 and erases internal
settings, saved Wi-Fi and app data. It is not a preserving update.

The paired SD overlay adds four paths: OBD app ELF/manifest, the new immutable
scene ELF, and BLE serial ELF. Merge its Apps and Drivers folders into the card
root. Do not format the card or delete existing apps, books, ROMs, fonts, saved
state or old immutable driver images. The paired image and SD overlay are
required together. Final delivery is held until the owner's requested time.
